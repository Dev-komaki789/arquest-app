## 1. 書くときに守ったルール

確定版 §1・§2.2・§2.3 から導かれる制約。**カードを足すときは毎回これに照らすこと。**

| | ルール | 理由 |
|---|---|---|
| 1 | **座標・エリア・実在の施設名に紐付けない** | §2.2。移動カードは曖昧な指示のみ。行き先の正解は存在しない |
| 2 | **どこで出ても無害な文面にする** | 下記「迷惑・危険をどこで止めるか」参照。**止める場所が他に無い** |
| 3 | **対人を要求しない** | §10。アプリの役割は外に出る理由を作ることであり、社交性を鍛えることではない |
| 4 | **攻撃性・自己否定を入れない** | アプリが単独で告げると額面通りに受け取られる |
| 5 | **危険な姿勢・行動を取らせない** | 後ろ向き歩き・車道に出る・よじ登る・立ち入り禁止に入るは書かない |
| 6 | **お金を使うお題は書いてよいが、撤退できる文面にする** | §1。金額の上限は設けないが、「買えなかった」で終われる形にする |
| 7 | **手ぶらで実行できる**（お金を使う系を除く） | 持ち物・他アプリを要求しない |

### 迷惑・危険をどこで止めるか（旧版から変わった最重要点）

旧版は「そもそもそこへ行かせない」＝**移動カード側（行き先のPOI選定）で止めていた。**
確定版では**移動カードも行き先を持たない**ため、この防波堤は存在しない。

→ **文面そのもので守るしかない。** 「無害なカード × まずい場所」の組み合わせは
利用者が着く場所を選ぶ以上どうしても起こりうるので、
**病院・学校・墓地の前で出ても成立してしまう文面か**を1枚ずつ確認して書いた。
（例：「大声を出そう」「知らない人に話しかけよう」は1枚も無い）

なお §2.4 の「通り道のスポット一覧」でOverpassから場所を拾うときは、
表示する側で次を除外すること。**カードではなく、そちらの問題として残る。**

```
amenity=hospital / clinic / doctors     病院
amenity=school / kindergarten           学校・幼稚園
amenity=police / fire_station           警察・消防
landuse=cemetery, amenity=grave_yard    墓地
amenity=funeral_hall                    斎場
```

### 実行不能になりうるのは「お金をつかう」系だけ

行動カードは場所を知らないまま引かれる（§2.3）。観察・言葉・写真のお題は
どこでも成立するが、**買い物のお題だけは店が無ければ実行できない。**

これは設計の穴ではなく、§2.3 の**引き直し2回がその受け皿**である。
ただし引き直しを使い切らせないよう、**お金系は全体の2割以下に抑えてある**（60枚中10枚）。

## 4. 旧版（座標に紐づく方式）から落としたもの

初版（2026-08-04）は、移動カードが `pois` の空間検索に紐づく設計で書かれていた。
確定版で**移動カードが座標を持たなくなった**ため、次を落とした。記録として残す。

| 落としたもの | 旧版での位置づけ | 落とした理由 |
|---|---|---|
| **型B ランドマーク到達 50通り**<br>（行ったことない{place}まで／一番近い{place}まで／名前がいちばん長い{place}まで 等） | 旧版の中心的価値。`visit_logs` と空間検索を使う | 確定版 §10 のとおり、行き先が実質的に座標として決まる方式そのものを不採用にしたため |
| 行き先の種類の対応表（公園＝`leisure=park` 等 10種） | 型Bの `{place}` に入る値 | 型Bごと不要 |
| 「型C（交通機関）は不採用」というルール | 旧§1「お金を使わせない」から | **確定版では休日に解禁**（§2.2）。逆になった |
| 「お金を使わせない」ルール | 旧§1 | **確定版では採用**（§1）。§3-6 として作り直した |
| 骨格×変数の構造（`card_variables`） | 100通りを14＋20の骨格で作る | 確定版のテーブルが `label text` 1列のため。**展開後の文面を直接持つ**形にした |

**型Bで作れた体験は、W-17〜W-19 として座標なしで作り直してある**（§2-1）。
アプリが場所を知らなくても「見つけるまで歩く」は成立する、というのが今回の発見。

## 5. 確定版のテーブルに対する気づき（提案・未反映）

書き出した結果として見えた点。**仕様書 §6 にはまだ反映していない。**

### 5-1. `action_cards` に写真フラグがあると分岐できる

§3-5 の6枚は、達成報告のあとに**日記の投稿へ進む**のが自然で、他の系統と画面遷移が違う。
`involves_spending` と同じ形で `requires_photo boolean` があると、実装側で判別できる。
（無くても「全クエストで撮影は任意」なので破綻はしない。**必須ではない。**）

### 5-2. 分類の列は今のところ不要

§3 の見出し（さがす／ことばにする 等）は読みやすさのためのもので、
抽選は全件から等確率で引く想定なので、テーブルに分類列は要らない。
**系統ごとの出現率を調整したくなったときに初めて必要になる。**

### 5-3. 変数の差し替えは、行を差し替える形になる

旧版は固有名詞を変数側に隔離して差し替え可能にしていた。
確定版は文面を直接持つので、古くなったカードは**その行を無効にする**ことになる。
削除すると過去の `quests.action_card_id` の参照が切れるため、
`is_active boolean default true` があると安全（**これも必須ではない**。運用で消さなければ済む）。

## 6. まだ決めていないこと

- **抽選の重みづけ。** いまは全カード等確率の想定。同じカードが続けて出たときの扱いは未決。
- **お金系10枚の比率が妥当か。** 引き直し2回で足りるかは、実際に歩いて試すまで分からない。
- **平日／休日の判定の境目。** 稼働時間帯をまたぐ深夜（金曜23時に引く等）をどちらとするか。
- **`transit_ok` を引いたのに電車に乗る気分でないときのパス。** 移動カードは引き直せない設計なので、
  「今日はやめる」で終われる導線が要るかどうか。
